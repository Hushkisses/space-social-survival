# DEV-012 Role Candidate Selection

## Goal

Generate three role candidates per player and allow each player to lock exactly one role while respecting per-role copy limits.

## Scope

- RoleCandidateSet
- RoleCandidateGenerator
- RoleSelectionResult
- RoleSelectionService
- deterministic seeded candidate generation
- per-role maxCopies enforcement
- one locked role per player
- rejection of roles outside a player's candidates
- Paper debug/selection commands
- JUnit coverage

## Rules

- each player receives exactly 3 distinct candidates
- candidate generation uses the six registered roles
- final selection must be one of the offered candidates
- selected roles respect RoleDefinition.maxCopies
- a player may lock only one role
- failed selection does not consume capacity
- same seed + same ordered player list reproduces the same candidate sets

## Important balance note

All six initial roles currently have maxCopies=2 because the design has not finalized which core roles should be singleton.
The selection engine supports maxCopies=1 without further architecture changes.

## Commands

```text
/space role prepare [seed]
/space role candidates
/space role choose <roleId>
/space role status
```

For DEV verification, `role prepare` uses current lobby membership. It may be run before the real briefing UI exists.

## Non-goals

- inventory GUI
- role icons
- briefing UI
- automatic transition to BRIEFING
- role-specific gameplay effects
- hidden alignment

## Completion criteria

- three distinct candidates per player
- deterministic seeded generation
- selection only from own candidates
- maxCopies enforced
- duplicate selection rejected
- Paper commands work
- tests/build/Paper validation pass
