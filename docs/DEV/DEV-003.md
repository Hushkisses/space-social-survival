# DEV-003 PlayerState

## Goal

Introduce a pure-Java player state model that is independent from Bukkit Player objects and safe to keep as match state across disconnects.

## Scope

- PlayerId
- PlayerState
- alive/dead state
- connected/disconnected state
- joinedAt / state-change timestamps
- idempotent reconnect/disconnect handling
- death transition
- unit tests
- status command update

## Non-goals

- role assignment
- objective assignment
- inventory persistence
- infection state
- scoring
- lobby join/leave orchestration
- database persistence

## Design

PlayerState is a domain object. It must not hold org.bukkit.entity.Player or other Paper-specific objects.

A player's Bukkit session may disappear and reconnect, but the match state remains in PlayerState.

## Tests

- new player starts alive and connected
- disconnect/reconnect changes connectivity only
- disconnect/reconnect is idempotent
- death is terminal for alive state
- death timestamp is recorded once
- player ID remains stable
- timestamps use injected Clock
