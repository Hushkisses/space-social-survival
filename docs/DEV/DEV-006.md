# DEV-006 Tile Registration

## Goal

Define reusable logical map-tile metadata and a registry that later map generation can use without knowing physical build coordinates.

## Scope

- TileId
- TileCategory
- ConnectionPointId
- ConnectionPointType
- ConnectionPointDefinition
- TileDefinition
- TileRegistry
- registration validation
- lookup/query methods
- unit tests

## Design rules

- tile metadata is pure Java and Paper-independent
- physical placement data is not stored here
- every tile has a logical ID and category
- every connection point ID is unique inside its tile
- connection point type is explicit
- duplicate tile IDs are rejected
- later DEV tickets may load these definitions from YAML and attach placement metadata

## Initial tile categories

- CORE
- CORRIDOR
- JUNCTION
- AIRLOCK
- AUXILIARY

## Initial connection point types

- DOOR
- AIRLOCK
- ELEVATOR
- MAINTENANCE
- TELEPORT

## Non-goals

- YAML tile loading
- NBT/world placement
- connection state
- teleport execution
- constrained random generation

## Completion criteria

- tile definitions can be registered and queried
- invalid/duplicate definitions are rejected
- connection point lookup works
- core tests pass
- full build passes
- Paper smoke test remains healthy
