# DEV-015 ShipState

## Goal

Introduce the authoritative core state for the ship's survival-critical systems and connect that state to DEV-014 crisis evaluation.

## Core metrics

Initial ShipState tracks:

- power
- oxygen
- hull stability
- reactor stability

Each metric is an integer percentage from 0 to 100.

The first three correspond directly to the initial common-goal design. Reactor stability is included because reactor condition is explicitly listed as a crisis driver.

## Crisis integration

ShipCrisisPressure converts ShipState into signed external crisis pressure.

Principles:

- healthy systems may slightly reduce time-based pressure
- degraded systems add pressure
- critical systems add much more pressure
- zero/near-zero survival systems can push a match rapidly toward crisis/collapse

Exact weights are development defaults and remain isolated in ShipCrisisPressure for later balance tuning.

## Paper debug commands

```text
/space ship status
/space ship set <power|oxygen|hull|reactor> <0-100>
/space ship reset
```

Runtime crisis status now reads the current ShipState pressure rather than neutral pressure.

## Non-goals

- facility-specific state
- power distribution topology
- oxygen simulation by room
- reactor heat/cooling sub-model
- engine/navigation state
- persistence

## Completion criteria

- all ship metrics validate 0..100
- state mutation is explicit and tested
- crisis pressure responds to degraded systems
- healthy state can offset some time pressure
- Paper status/set/reset commands work
- runtime crisis evaluator uses live ShipState pressure
- tests/build/Paper validation pass
