# DEV-005 Sector/Room/Connection Model

## Goal

Create the logical map graph model used by later tile registration, teleport connections, and constrained map generation.

## Scope

- SectorId
- RoomId
- ConnectionId
- Sector
- Room
- Connection
- MapGraph
- graph validation
- adjacency queries
- unit tests

## Design rules

- game logic uses logical IDs rather than physical coordinates
- every Room belongs to one Sector
- every Connection links two distinct Rooms
- a Connection is undirected at the logical graph layer
- duplicate IDs are rejected
- connections to unknown Rooms are rejected
- self-connections are rejected
- physical placement, teleport coordinates, and access state are deferred to later DEV tickets

## Non-goals

- tile registration
- world coordinates
- NBT placement
- teleport implementation
- connection access states
- random map generation

## Completion criteria

- map graph can register sectors, rooms, and logical connections
- graph integrity rules are enforced
- adjacency can be queried from either endpoint
- core tests pass
- full build passes
- Paper smoke test remains healthy
