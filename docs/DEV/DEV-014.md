# DEV-014 Game Timer & Crisis

## Goal

Add an authoritative match timer and crisis-stage evaluator while keeping future ShipState inputs decoupled.

## Design

Crisis stages:

- STABLE
- ALERT
- CRISIS
- COLLAPSE

Time raises baseline crisis pressure, but time alone does not force collapse at the nominal 45-minute target.

For the current 45-minute default:

- ALERT baseline begins around 15 minutes
- CRISIS baseline begins around 30 minutes
- COLLAPSE baseline begins around 60 minutes

The collapse threshold is derived from target match duration (4/3 of target), matching the design intent that a well-managed ship may survive 50–60 minutes.

Future ShipState / facility / infection / fire / creature systems add signed crisis pressure through CrisisFactors without changing the timer model.

## Scope

- GameTimer
- MatchTimeSnapshot
- CrisisStage
- CrisisFactors
- CrisisThresholds
- CrisisEvaluator
- configurable target match duration integration
- Paper runtime scheduler
- /space runtime start|status|stop
- Korean runtime status output
- JUnit coverage

## Crisis calculation

A normalized time score is calculated relative to target match duration.

External crisis pressure is a signed integer:

- positive = ship condition is worsening
- negative = ship condition is unusually stable/recovered

DEV-014 uses external pressure 0 because ShipState does not exist yet.

Threshold values are data objects, not hardcoded inside the evaluator.

## Non-goals

- ShipState
- facility damage
- oxygen / power / hull calculations
- infection/fire/alien pressure
- return-phase countdown
- HUD boss bar

## Completion criteria

- timer starts once and reports elapsed/remaining target time
- timer can be stopped
- crisis stage is deterministic for elapsed time and external pressure
- external pressure can accelerate or delay crisis stage
- Paper scheduler updates runtime state
- tests/build/Paper smoke validation pass
