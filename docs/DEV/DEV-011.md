# DEV-011 Role Framework

## Goal

Create the pure-Java role model used by later candidate selection, briefing, facility privileges, and action bonuses.

## Source design

Initial roles:

- Engineer
- Medic
- Security
- Researcher
- Navigation/Communications
- Cargo/Maintenance

A role is a professional specialty, not an alignment.

All players retain basic actions; roles provide passive bonuses and privileged/advanced capabilities.

## Scope

- RoleId
- RoleDefinition
- RolePassive
- RoleCapability
- RoleRegistry
- default six-role catalog
- role duplicate-limit metadata
- unit tests

## Initial duplicate limits

The design says most roles may have up to 2 copies while some core roles may later prefer a limit of 1.

DEV-011 therefore supports per-role limits but does not permanently decide which roles are singleton. All six initial defaults use maxCopies=2 until candidate-selection balancing is finalized.

## Non-goals

- candidate generation
- choosing a role
- binding a role to PlayerState
- alignment/traitor state
- facility implementation
- actual repair/heal/combat bonuses
- GUI

## Completion criteria

- six initial roles are available from one catalog
- IDs are unique
- passive/capability metadata matches game design
- duplicate limits validate
- registry lookup works
- tests/build/Paper smoke test pass
